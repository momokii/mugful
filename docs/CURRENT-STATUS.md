The Bahasa-first legal notices identify the current server-owned `terms-v1` and `privacy-v1` versions. - Todo 6 is accepted: `0004_couple_onboarding.sql` creates couple spaces, memberships, and hash-only invite records; PostgreSQL enforces one active space per account. Verified sessions can create a seven-day, single-use `/join#token=…` invite, another verified account can accept it, and either member can end the space. Create/accept use account and invitation/space locks; ending immediately revokes memberships and pending invites while recording a 30-day deletion grace timestamp. API integration against an isolated migrated PostgreSQL database passes create → accept → replay rejection → end/revocation. `/onboarding` and `/join` use same-origin CSRF mutations and fragment removal; `/join` additionally uses `no-store` and `no-referrer`. Their Brave Chromium matrix passed at mobile, tablet, and desktop sizes.

- Todo 7A prompt catalog persistence is implemented and verified: additive `0005_prompt_catalog.sql` adds `prompts`, immutable `prompt_versions` (text/category/version with one active version per prompt through a partial unique index), and `prompt_audit_events` (created/updated/retired with version-transition invariants) without deleting history. The `prompt-catalog` schema module validates canonical text, category slugs, version numbers, and audit transitions with focused unit coverage. The migration was applied to a fresh local PostgreSQL Compose database, and a transactional probe proved the single-active invariant rejects a second active version while create → retire → replace flows audit correctly, leaving zero probe rows.
- Todo 7B1 prompt catalog service is implemented and verified: `createPromptCatalogService` performs transactional create (version 1 active), update (retire current, add next version), retire (single audit event referencing its own version), and active-catalog listing, all validated through the prompt schema module and recorded in `prompt_audit_events`. - Todo 7B2a superadmin authorization persistence is implemented and verified: additive `0006_superadmin_authorization.sql` adds `superadmin_accounts` (grant/revocation of the operational role on a normal account), `superadmin_passkey_credentials` (base64url credential IDs, COSE public keys, signature counters, one active-credential lookup index), `superadmin_totp_recovery` (160-bit RFC 4648 base32 secrets, 6/8 digits, 30/60-second periods, replay-resistant `last_used_step`), and `superadmin_audit_events` (grant, revocation, passkey/TOTP enrollment lifecycle, and authentication outcomes). The `authorization` schema module validates credential IDs, COSE keys, counters, base32 secrets, TOTP parameters, and audit actions with focused unit coverage, and a gated introspection test verifies all tables, constraints, and indexes against a migrated real PostgreSQL database.
- Todo 7B2b superadmin MFA service is implemented and verified: the `totp` module implements RFC 6238 (RFC 4648 base32 decoding, HMAC-SHA1 dynamic truncation, ±1-step acceptance window, and step-based replay classification) and reproduces every RFC 6238 SHA-1 reference vector in unit tests. `createSuperadminService` performs transactional grant/re-grant/revoke with idempotency, passkey registration gated on an active grant with duplicate-credential rejection, passkey revocation, TOTP enrollment with re-enrollment resets, and TOTP recovery verification that consumes the matched step, distinguishes mismatch from replay, and audits success and failure outcomes. Five real-PostgreSQL integration tests cover the role lifecycle, passkey gating and duplicates, single revocation, replay protection with consumed-step persistence, and failure auditing.
